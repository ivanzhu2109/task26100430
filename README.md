# fifoq

本地文件持久化的 FIFO 消息库（仅 Go 标准库）。固定 3 个消费组，
均从队列创建时开始订阅；支持原子批量发布、消费确认、物理压缩
与崩溃恢复。

## 使用

```go
q, err := fifoq.Open("/path/to/dir") // 不存在则创建；已存在则自动恢复
if err != nil { ... }
defer q.Close()

// 原子发布一批消息，ID 按发布顺序严格递增（从 1 开始）
ids, err := q.Publish([][]byte{[]byte("a"), []byte("b")})

// 按 ID 递增读取该组尚未确认的消息；不改变消费状态，可重复读
msgs, err := q.Read(0, 100) // group ∈ [0,3)，limit 条

// 原子确认一组 ID；允许乱序、重复确认，组间互不影响
err = q.Ack(0, []uint64{ids[1], ids[0]})

// 回收所有组均已确认的消息；不改变任何组后续 Read 的逻辑结果
err = q.Compact()
```

约束：调用需在进程内串行执行（库内已加互斥锁），同一目录不得
被多个进程同时打开。可容忍进程被强制终止（SIGKILL）；不保证
整机断电场景。

## 存储与恢复

目录内文件：

- `data.log`：追加式记录日志。头部含基准偏移；每条记录带 magic、
  长度与 CRC32，整批一次写入并 fsync，崩溃产生的撕裂尾部在恢复
  时截断，不会遮蔽后续提交。
- `snap.dat`：Compact 产出的快照（存活消息正文 + 每组确认位 +
  nextID + 日志水位），先写 `snap.tmp`、fsync 后原子 rename，
  再截断日志。崩溃于任一阶段均可由水位对齐恢复。
- 恢复时先删残留 `snap.tmp`，再加载快照，最后跳过快照水位之前
  的记录重放日志。

Publish/Ack 正常路径只追加一条记录（写入量随输入增长）；
Compact 后目录总大小 ≤ 2×存活正文 + 256B×存活条数 + 64KiB。

## 测试

```sh
go test ./...
```

覆盖：三组交错/乱序/重复确认 + 压缩重开后逐组核对正文与 ID；
子进程 SIGKILL 注入 Publish/Ack 半写、Compact 三阶段中断；
全部确认后压缩为空再继续发布与旧 Ack 重放；10 万条积压下小
操作的实际写入量（无隐藏历史重写）；空正文与二进制正文。
