# mq — 本地文件持久化 FIFO 消息库

纯 Go 标准库实现，无外部依赖。固定 3 个消费组，均从队列创建时开始订阅；
消息为不透明字节串，ID 自 1 起严格递增、绝不复用。

## 特性

- **Publish**：原子发布一批消息，批内保持输入顺序，返回每条消息的 ID。
- **Read**：按 ID 递增返回某组未确认的消息，不改变消费状态（可重复读）。
- **Ack**：原子确认一组 ID，允许乱序与重复确认，组间互不影响。
- **Compact**：物理回收所有组均已确认的消息正文与历史记录，原子切换。
- **崩溃恢复**：重新打开目录时自动截断半写尾部、清理压缩残留；
  未返回的 Publish/Ack 要么整体生效要么完全不生效。

## 使用

```go
q, err := mq.Open("/path/to/dir") // 不存在则创建；自动恢复
if err != nil { ... }
defer q.Close()

ids, _ := q.Publish([][]byte{[]byte("a"), []byte("b")}) // ids = [1 2]

msgs, _ := q.Read(0, 100)   // 组 0 读取最多 100 条未确认消息
_ = q.Ack(0, []uint64{ids[1], ids[0]}) // 乱序确认

_ = q.Compact()             // 回收全部组都已确认的消息
```

## 存储与一致性设计

- 目录内单个追加日志 `mq.log`，记录帧为
  `type u32 | len u32 | crc32 u32 | payload`，CRC 覆盖帧头与正文。
- 记录类型：`publish`（首 ID + 批量正文）、`ack`（组 + ID 列表）、
  `snapshot`（下一 ID + 存活消息及其各组待确认位掩码）。
- Publish/Ack 正常路径只追加一条记录并 fsync，写入量只随本次输入增长。
- 恢复时顺序扫描，首个不完整或校验失败的记录起视为半写尾部并截断，
  后续提交不会被残留数据遮蔽。
- Compact 把快照写入 `mq.log.new`、fsync、原子 rename、再 fsync 目录；
  崩溃时新旧日志必有一份完整可用，残留的 `.new` 文件在打开时清理。
- ID 由日志中的快照与发布记录共同恢复，全部确认并压缩后也不会复用。

## 测试

```sh
go test ./...
```

覆盖：三组交错乱序确认后压缩重开并逐组核对正文；全部确认后压缩为空、
继续发布与重复旧 Ack；10 万条积压下少量 Publish/Ack 的实际文件写入量；
子进程在真实写路径故障点被 SIGKILL 强杀（Publish/Ack 半写与未 fsync、
Compact 文件切换与清理中断）后的恢复与继续使用。
